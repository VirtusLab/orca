Summarise the following work into a PR title and a PR description body.

- Title: one line, imperative, saying what the PR does.
- Body: as short as possible. One to three short paragraphs, or a short bullet
  list when there are several separate changes. Use plain, simple language.
- Say what changed, why (only as the context states it), and anything a
  reviewer must know that the diff doesn't make obvious.
- When a context section appears above the diff, anchor the description to it:
  reference the originating issue, user ask, or other anchor it supplies.
- State only facts visible in the diff or given in the context. Never guess or
  invent claims about CI, platforms, environments, performance, motivation,
  testing done, or consequences.
- Don't restate line by line what the code does, and don't list every file
  touched.
- No filler or marketing phrasing ("This change improves…", "This ensures…",
  "robust", "seamless").
